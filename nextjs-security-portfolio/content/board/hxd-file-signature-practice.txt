제목: [디지털 포렌식] HxD로 숨겨진 ZIP 추출하고 JPG 복원하기
작성자: 박시우

멋쟁이사자처럼 14기 디지털 포렌식 실습에서 HxD로 이미지 파일 내부의 데이터를 분석했다. PNG에 숨겨진 ZIP을 추출하고, JPG와 ZIP이 섞인 파일에서 각각의 데이터를 분리하는 과정을 정리했다.

1. 실습 목표와 사용 도구

사용 도구는 파일의 바이트를 16진수로 확인하고 편집할 수 있는 HxD이다. 이번 실습의 목표는 확장자만 보고 파일을 판단하는 대신, 내부 시그니처를 찾아 데이터의 경계를 파악하는 것이었다.

이번에 확인한 주요 값은 다음과 같다.
• ZIP 로컬 파일 헤더 시작: 50 4B 03 04
• ZIP 중앙 디렉터리 끝 레코드(EOCD) 시작: 50 4B 05 06
• JPG 이미지 시작(SOI): FF D8
• JPG 이미지 끝(EOI): FF D9

원본 보고서의 JPG 시그니처 표기인 FF 08 / FF 09는 이 글에서 FF D8 / FF D9로 바로잡았다.

2. 실습 1 — PNG 파일에서 ZIP 추출

첫 번째 문제는 PNG 파일 내부에 숨겨진 ZIP 데이터를 찾는 것이었다. 겉으로는 이미지 파일이지만 내부를 살펴보면 별도의 파일 데이터를 찾을 수 있었다.

① HxD에서 실습용 PNG 파일을 열었다.
② Ctrl+F로 검색 창을 열고, 16진수 값 검색으로 50 4B 03 04를 찾아 ZIP 데이터의 시작 후보를 확인했다.
③ 50 4B 05 06도 검색해 ZIP의 끝부분을 판단할 단서를 찾았다.
④ ZIP에 해당하는 데이터 영역을 복사해 새 파일에 붙여넣고 .zip 확장자로 저장했다.

이 과정을 통해 이미지 안에 숨겨져 있던 ZIP 파일을 별도 파일로 추출했다. 하나의 파일 안에 다른 형식의 데이터가 포함될 수 있다는 것을 직접 확인한 실습이었다.

여기서 주의할 점이 있다. 50 4B 05 06은 ZIP 전체의 마지막 4바이트가 아니라 EOCD 레코드가 시작되는 값이다. 해당 값까지만 복사하면 뒤에 필요한 정보가 빠질 수 있다. 일반적인 ZIP에서는 EOCD의 고정 부분과 가변 길이 주석까지 포함해 끝을 확인해야 한다. 시그니처 검색 결과만으로 추출 범위가 확정되는 것은 아니다.

3. 실습 2 — JPG와 ZIP 분리, 이미지 복원

두 번째 문제에서는 깨진 JPG 파일 내부의 ZIP 데이터를 찾고 이미지와 ZIP을 분리했다.

처음에는 ZIP 시작 시그니처와 EOCD 시작 시그니처를 찾아 그 구간을 삭제해 보았다. 하지만 EOCD 뒤의 어느 부분까지 ZIP에 속하는지 정확하게 판단하지 못했고, 삭제한 뒤에도 JPG가 완전한 상태로 보이지 않았다.

이후 JPG 자체의 시작과 끝 시그니처를 기준으로 이미지 데이터 영역을 다시 찾았다. 해당 영역을 추출해 JPG 파일로 저장했고, 보고서 마지막 화면처럼 정상적으로 표시되는 이미지를 복원할 수 있었다. 실습 보고서에는 JPG와 숨겨진 ZIP을 각각 분리한 결과도 정리했다.

이 과정에서 가장 크게 배운 점은 불필요해 보이는 데이터를 지우는 것만으로 파일이 복원되지는 않는다는 것이다. 남길 데이터가 어디에서 시작하고 끝나는지 이해하는 과정이 필요했다.

4. 실습을 통해 배운 점

• 확장자는 파일 내부의 모든 정보를 설명하지 않는다. PNG나 JPG 내부에서도 ZIP 데이터를 발견할 수 있었다.
• 시그니처는 파일의 위치와 구조를 찾는 단서다. 실제 분리 범위는 주변 구조까지 살펴보고 판단해야 한다.
• ZIP의 EOCD 시작과 파일 전체의 끝은 구분해야 한다. 경계를 잘못 잡으면 파일이 불완전해질 수 있다.
• 추출한 파일은 저장한 뒤 실제로 열리는지 확인해야 한다. ZIP은 압축 해제와 무결성을 확인하고, 이미지는 정상적으로 표시되는지 살펴보는 것이 좋다.

이번 실습은 단순히 16진수 값을 검색하는 작업에서 시작했지만, 결국 파일 형식의 구조를 이해해야 정확하게 분리하고 복원할 수 있다는 점을 배우는 과정이었다. 특히 첫 시도에서 이미지가 완전히 복원되지 않았던 경험이 데이터 경계를 확인하는 중요성을 이해하는 데 도움이 되었다.
